# Handover — M2 Activation (2026-08-10)

Follows the ICM/MWP handover contract (human-reviewed handoff between iterations; see
AGENTS.md). Roadmap status: **M1 → Done, M2 → Done (this iteration), M3 → Current**.

## Task

**M2 — Activation** (roadmap/README.md): `ActivationBackend` contract — hot-corner detection
(debounced, edge-triggered) + global `Super + T` toggle + `Esc` dismiss. Done = verified live on
the X11 session: overlay starts hidden, appears on top-right corner dwell or `Super + T`, `Esc`
hides it, focus never stolen.

## What was done

- `src/backend/mod.rs` — `ActivationBackend` facade contract (proposal §10): `start()`,
  `set_overlay_visible()`; `ActivationEvent` (`CornerEntered`/`CornerLeft`/`Toggle`/`Dismiss`)
  and `Monitor` value types. Edge-triggered; debounce is policy, lives in the consumer.
- `src/backend/x11.rs` — `X11ActivationBackend`:
  - **XI2 pointer motion** (`XISelectEvents`, `XI_Motion`, all devices) on the root window —
    per-client selection, event-driven, no polling (proposal §13).
  - **Hot corner**: top-right 4 px region of every monitor (RandR 1.5 monitors, fallback to root
    geometry), edge-triggered enter/leave state machine with interior mutability.
  - **`Super + T`**: core passive grab for the daemon's lifetime, all four NumLock/CapsLock
    lock-state combinations. **`Esc`**: grabbed only while the overlay is visible, released on
    hide (the overlay never has focus, so dismissal cannot rely on window focus — M1's
    `input=False` guarantees that).
  - **Event loop integration**: `install_event_source()` attaches a glib source watching a dup
    of the X connection fd (`gio::Socket`), so events arrive on the main context with zero
    polling and zero extra threads.
- `src/main.rs` — glue: overlay starts **hidden**; corner entry starts a 200 ms dwell timer
  (canceled on corner leave) before showing; `Super + T` toggles; `Esc` dismisses. Activation
  failures degrade to M1 behavior (overlay always visible) with a logged warning.
- `Cargo.toml` — `gio` (fd source), `x11rb` features `randr` + `xinput`.
- `AGENTS.md` — added the uncertainty rule: unknown/unset decisions default to the most common
  idiomatic practice instead of blocking on taste questions.
- `roadmap/README.md` — M2 Done, M3 Current.

## What was done differently (and why)

1. **No root-window core event mask.** The first attempt selected `POINTER_MOTION|KEY_PRESS` on
   the root via `ChangeWindowAttributes` (read-mask-then-OR, to preserve the WM's bits) — the
   server answered `BadAccess`: the WM owns `SUBSTRUCTURE_REDIRECT`, and the mask replacement
   would have clobbered it. Switched to **XI2 `XISelectEvents`**, whose selection is per-client
   and independent of the core mask. Keyboard stays on core `XGrabKey` (delivered without any
   event selection), so XI2 selects `XI_Motion` only — selecting XI key events too would
   double-deliver keys that the core grab already routes.
2. **`gio::Socket` `create_source`, not `DatagramBased`.** `g_datagram_based_create_source` on
   a `GSocket` returns `NULL` (GLib-CRITICAL, process died). `g_socket_create_source`
   (`SocketExtManual`) is the correct GSocket source. The fd is dup'd because `Socket::from_fd`
   takes ownership.
3. **Dwell debounce lives in the glue (main.rs), not the backend** — the backend reports
   edge-triggered enter/leave; the 200 ms dwell timer is show/hide policy. This keeps the
   facade free of timing policy and lets M3's auto-hide timer reuse the same `CornerLeft` event.
4. **`poll()` was dropped from the trait** during implementation (dead code): the X11 event
   source is the delivery mechanism for M2; a poll-based contract adds nothing yet. Revisit
   when a second backend or tests need it.
5. **GTK `Application` handoff trap** (verification): a stale first instance holds the
   `application_id`; new instances register to it and exit silently, so the tested binary was
   never the running one. Kill stale instances by exact name (`pkill -x hover-clock`) before
   iterating.

## Verification

- `cargo build`, `cargo clippy`, `cargo test` — clean, no warnings.
- Live on xfwm4 4.20 (DISPLAY=:0.0), single monitor 1366x768:
  - Startup: no window mapped (overlay hidden).
  - Corner dwell (top-right, >200 ms) → `IsViewable`; quick pass through the corner (<200 ms)
    → stays hidden (debounce works).
  - `Super + T` → toggles both ways; `Esc` → `IsUnMapped`.
  - EWMH hints intact after show/hide cycles: `_NET_WM_STATE = SKIP_PAGER, SKIP_TASKBAR, ABOVE`,
    `_NET_WM_WINDOW_TYPE = NOTIFICATION` (M1's post-map re-apply holds).
  - Focus never stolen: active window stays the previously focused app.
- Caveat: during verification the user's physical pointer was also active; corner tests were
  repeated until unambiguous.

## Open questions

- **Overlay placement**: xfwm4 places the notification window near the screen center (verified
  `+564+344`, `+568+380` on 1366x768), not at the trigger corner. "Overlay appears at the
  triggered monitor's top-right" is the common approach (GNOME-like) — M3 needs a placement
  mechanism (GTK4 has no `move()`; `present_at()` steals focus and is banned, so placement will
  go through the X11 `WindowBackend` or a dedicated backend call).
- Corner-triggered show while the overlay is already visible is a no-op by construction (the
  glue checks nothing — `set_visible(true)` on a visible window is harmless); re-entry after
  `CornerLeft` re-fires. M3's auto-hide interacts here: leaving the corner should start the
  auto-hide timer, not dismiss instantly (interaction model §5: "move mouse away → auto-hide
  (debounced)").
- `keysym::T` uses `XK_T`/`XK_t` scan of the keyboard mapping; exotic layouts where the T key
  has neither are unsupported (grab silently skipped — hot corner still works).
- `application_id` is still the M0 leftover (`com.github.gtk-rs.examples.clock`); revisit with
  the binary's real identity (M4/CLI milestone).
